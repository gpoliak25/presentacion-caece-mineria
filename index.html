04 / Los Modelos

Del overfitting al ensemble — dos estrategias

⚠️
El primer modelo nos engañó: 100% de accuracy
Un árbol sin restricciones memorizó cada cliente (overfitting). En datos nuevos, fallaba. Un 100% casi nunca es buena noticia en ML.
🌳
Modelo 1 — CART
Árbol de decisión con regularización
  • En cada nodo hace una pregunta binaria (ej. ¿age > 35?) para dividir los datos
  • max_depth=5 — limita la profundidad para no memorizar el training set
  • min_samples_leaf=20 — cada hoja necesita al menos 20 clientes reales
  • class_weight='balanced' — da 7× más peso al 12% positivo
  • Ventaja: completamente interpretable — se puede ver cada decisión
max_depth=5 min_samples_leaf=20 class_weight='balanced' random_state=42
Resultado en test set

🌲
Modelo 2 — Random Forest
Ensemble de 100 árboles con votación
  • 100 árboles distintos, cada uno entrenado con submuestra aleatoria de datos y variables
  • La predicción final es el promedio de probabilidades — reduce el ruido de cada árbol individual
  • Mismos hiperparámetros que CART para una comparación justa
  • Reduce overfitting naturalmente al promediar predicciones diversas
  • Desventaja: menos interpretable que un árbol único, pero más robusto

Remoción de Data Leakage — variable duration

Paso 04
One-Hot Encoding vs LabelEncoder
⚠ Antes — problema detectado
LabelEncoder introduce orden falso entre categorías

LabelEncoder asigna enteros a las categorías. El modelo interpreta admin=0 < blue-collar=1 < entrepreneur=2, como si hubiera una jerarquía numérica entre profesiones. Eso es matemáticamente incorrecto.

# Incorrecto para variables nominales:
from sklearn.preprocessing import LabelEncoder
le = LabelEncoder()
df['job'] = le.fit_transform(df['job'])

# Resultado:
# admin=0, blue-collar=1, entrepreneur=2...
# El modelo cree que entrepreneur > blue-collar
# Eso no tiene ningún sentido real
✓ Después — ajuste aplicado
pd.get_dummies unifica train+test antes de codificar

One-Hot crea una columna binaria por categoría. Sin jerarquía artificial. Además, concatenar train y test antes garantiza que ambos tengan exactamente las mismas columnas dummies.

# Correcto: concatenar primero, luego codificar
X_total = pd.concat([X_train, X_test], axis=0)
X_total = pd.get_dummies(X_total, drop_first=True)

X_train_enc = X_total.iloc[:len(X_train), :]
X_test_enc  = X_total.iloc[len(X_train):, :]

# Resultado: job_admin, job_blue.collar... (binario)
# Sin orden falso · Columnas idénticas garantizadas ✓
print(X_train_enc.shape)
# (34812, 42)  ← 15 vars → 42 columnas dummies
✂️
Paso 05
Train / Test Split — el rol de stratify
⚠ Antes — problema detectado
Sin stratify → distribución aleatoria desequilibrada

Sin stratify, el split es puramente aleatorio. Con solo 12% de positivos en el dataset, una mala suerte podría concentrar casi todos los positivos en train y dejar el test sin ejemplos de la clase "sí".

# Sin stratify — riesgo de distribución desigual:
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.3, random_state=42
)

# Posible resultado en una mala partición:
print(y_train.mean())  # 0.145  (14.5% positivos)
print(y_test.mean())   # 0.062  (6.2% positivos) !
# El test ya no representa la realidad del problema
✓ Después — ajuste aplicado
stratify=y garantiza la misma proporción en ambas particiones

Con stratify=y, scikit-learn garantiza que train y test tengan exactamente la misma proporción de positivos que el dataset original. La evaluación del modelo es justa y representativa.

# Con stratify — distribución garantizada:
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.3, random_state=42,
    stratify=y  ← clave
)

print(y_train.mean())  # 0.117  (11.7%) ✓
print(y_test.mean())   # 0.117  (11.7%) ✓
# Misma proporción que el dataset original
# train: 34.812 filas · test: 14.919 filas ✓
⚙️
Paso 06
Entrenamiento — del overfitting al modelo controlado
⚠ Antes — problema detectado
Árbol sin restricciones → 100% accuracy = overfitting

Un árbol de decisión sin límites crea ramas para cada cliente individual del training set, memorizando todos los datos. Resultado perfecto en entrenamiento, pésimo en datos nuevos.

# Sin restricciones — overfitting severo:
modelo = DecisionTreeClassifier()
modelo.fit(X_train_enc, y_train_enc)

print(accuracy_score(y_train_enc,
      modelo.predict(X_train_enc)))
# 1.0000  ← 100% en training (memorización)

print(accuracy_score(y_test_enc,
      modelo.predict(X_test_enc)))
# 0.7100  ← ya no generaliza bien
✓ Después — ajuste aplicado
Regularización + class_weight → modelo honesto y útil

Con max_depth=5 y min_samples_leaf=20, el árbol solo puede hacer preguntas relevantes. class_weight='balanced' obliga al modelo a prestar atención al 12% de positivos que nos importan.

# CART controlado:
cart = DecisionTreeClassifier(
    max_depth=5, min_samples_leaf=20,
    class_weight='balanced', random_state=42
)
print(auc_cart)   # 0.76  ✓ generaliza bien

# Random Forest (100 árboles):
rf = RandomForestClassifier(
    n_estimators=100, max_depth=5,
    min_samples_leaf=20, class_weight='balanced'
)
print(auc_rf)     # 0.79  ✓ mejor generalización
